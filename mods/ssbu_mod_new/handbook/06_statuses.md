# Statuses

Tiers: **A** hardware-confirmed (console or decoded crash report) - **B** measured offline by a script that still exists - **C** read from pinned third-party source - **D** hypothesis. Anything without a tier below is A/B unless marked otherwise. Paths in the source column refer to the *old* workspace (`modpack_test_1`); the same material now lives under `projects/*/history/`, `dumps/` and `evidence/`.

- **Recovering a donor's status code** (WuBoytH dumps have none for G&W): `tools/nro_decomp/` flattens `lua2cpp_<f>.nro`, lists every `(status, condition, fn)` from `sv_set_status_func` (`status_table.py`) and decompiles with headless Ghidra (`run_ghidra.sh`, ~3 min first run). Conditions include INIT/EXEC, not only PRE/MAIN/END - G&W's up-B direction logic is in EXEC. Ghidra drops lua-stack pushes and `global_table` indices; confirm those from disassembly. Example output: `refs/gamewatch_special_hi/`. (B, smoke test)
- Custom status ids start at `FIGHTER_<X>_STATUS_KIND_NUM`: eflame `0x1EE` (last real `0x1ED`), elight `0x1F1`, G&W c07 swap used `0x210-0x21a`, `0x220`. Keep the literal and `assert_eq!` against the const at load (LuaConst deref is not const). (B)
- **A block of ids is allocated, not one id per move**: pgwr holds `0x1EE`-`0x1F8` for Monkey Flip's eleven phases and `0x1F9`/`0x1FA` for up-B's FALL/CLOSE (`src/pgwr/plugin/src/status/mod.rs` is the table). Allocate from the end of the used block, never from the lowest free number - up-B Fire's plan named `0x1EF`/`0x1F0` while they belonged to nobody, and both are now taken. (B)
- 13.0.4 common table: `SPECIAL_N 0x1DC, SPECIAL_S 0x1DD, SPECIAL_HI 0x1DE, SPECIAL_LW 0x1DF`, `COMMON_NUM 0x1DC`, `MAX 0x1E1`; **no `SPECIAL_S_START`**. (B)
- Bindings gaps: `StatusModule::change_status` does not exist -> `change_status_request_from_script(ma, kind, true)`; `CancelModule` has only `enable_cancel`; no `FIGHTER_STATUS_KIND_RESET` (use WAIT); `set_default_int64` takes `u64`, `set_mesh_visibility` takes `Hash40`; a status callback must return `L2CValue::new_int(0)` (never `default()`). `MotionModule::change_motion` takes 8 args, game passes `(ma, hash, 0.0, 1.0, false, 0.0, false, false)`. (C/B)
- Do not branch on `status_kind` inside `Pre` to tell phases apart (Hi3 air entry ran ground kinetics). Register distinct Pre callbacks / pass the phase. Preserve `FIGHTER_STATUS_ATTR_START_TURN` when redirecting a special. (A, Hi3)
- Only the active form reliably gets `on_line(Main)`; dormant partner callbacks are UNVERIFIED. (guide §4.9)
- Never force state every frame (visibility, hit status, position) - masks transfer failures. (A, swap history)
- Monkey Flip availability is instance state, separate from its per-move phase reset. **B:** `tools/audit_diddy_special_lockout.py` 1.0.0 on the shipped Diddy NRO pins instructions/hash in `refs/diddy_monkey_flip/special_lockout.json`: JUMP end to FALL sets the side-B input lock; KICK/STICK_ATTACK2 end to FLIP_FALL sets the general lock. Callback `0x7920` disables HI/S/LW for the general flag, S for the side flag. Recipient code must own those flags and compose with Fire's existing availability callback. **B, implemented 2026-10-02 (T-0053); D until tested:** `monkey_flip::Locks` holds both flags per entry **owned by the battle object that set them**, and only that object may clear them - Pyra and Mythra share an entry id, so an entry-keyed record was re-owned, and silently unlocked, by Mythra's landing; a refused refresh logs one `SWAPGUARD` line. Refresh stays on the native landing/ledge/hit/reset/stock events, and the START phase reset still cannot clear either flag. Finding: `kb/findings/monkey-flip-aerial-locks-need-an-object-owned-record.md`. 0.20.7 shipped only the side-only lock; it covers neither the kick path nor the swap.
- Air kinetics: take gravity/terminal speed from the donor PRC, effects from the **recipient**; check exit frame against the last ACMD frame (finisher at 47-48 was never reached). (A, Hi3 .c/.d)
- **A slow fall has a per-phase exit, so tuning it downward cannot loop.** Hi3's aerial phase leaves to `LANDING_FALL_SPECIAL` on ground contact and to `FALL_SPECIAL` when the donor motion ends, and its `Exec` callback is registered on the phase alone, so lowering gravity stops applying the instant the phase ends. A "permanent hover" needs the *descent* to stop, not merely to slow - and the temptation to keep lowering is bounded by reading the descent per hit window against the box band (`tools/audit_hero_spin_airtime.py`). (B, 2026-10-03)
